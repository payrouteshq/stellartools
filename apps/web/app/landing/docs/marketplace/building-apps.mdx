StellarTools marketplace apps are web apps that run inside an `iframe` embedded directly in the dashboard. Your app receives the active organization's context, a signed app token for authenticating server-side requests, and can subscribe to real-time payment events via webhooks.

## Install the bridge

```bash
npm install @stellartools/app-embed-bridge
```

## Initialize in your React app

Call `stellar.init()` once on mount. It reads context from URL params injected by StellarTools, starts an auto-resize observer so your iframe fits its content, and returns the context object.

```tsx
import { useEffect, useState } from "react";
import { stellar } from "@stellartools/app-embed-bridge";

export default function App() {
  const [ctx, setCtx] = useState(null);

  useEffect(() => {
    const context = stellar.init((update) => {
      setCtx((prev) => ({ ...prev, ...update }));
    });
    setCtx(context);
  }, []);

  if (!ctx) return null;

  return <div>Org: {ctx.organizationId} · Env: {ctx.environment}</div>;
}
```

### Context fields

| Field            | Type                     | Description                                                                 |
| ---------------- | ------------------------ | --------------------------------------------------------------------------- |
| `organizationId` | `string`                 | The active organization                                                     |
| `environment`    | `"testnet" \| "mainnet"` | Which network the org is on                                                 |
| `theme`          | `"light" \| "dark"`      | The dashboard theme                                                         |
| `pathname`       | `string`                 | The current dashboard route                                                 |
| `installationId` | `string`                 | Unique ID for this org's installation — use it to key your backend records  |
| `appToken`       | `string`                 | Signed JWT issued by StellarTools. Pass this to your BFF routes to authenticate server-side requests |

### Host communication

```ts
stellar.navigate("/payments"); // push the user to a dashboard route
stellar.reload();              // tell the host to refetch its data
```

## Server-side routes (BFF pattern)

Your iframe is a client-only app — it can't hold secrets. For anything that requires an API key or a call back to StellarTools, use a BFF (backend-for-frontend) route in your app's server layer.

The iframe passes `appToken` as a `Bearer` token. Your BFF verifies it, then uses it to call StellarTools.

### Verify the app token

```ts
// app/api/your-route/route.ts
import { verifyJwt } from "@stellartools/app-embed-bridge/server";

type AppTokenPayload = {
  instId: string;
  orgId: string;
  scopes: string[];
  env: string;
  settings: Record<string, unknown>;
};

export async function GET(req: Request) {
  const appToken = req.headers.get("authorization")?.replace(/^Bearer\s+/i, "");
  if (!appToken) return Response.json({ error: "Unauthorized" }, { status: 401 });

  let payload: AppTokenPayload;
  try {
    payload = verifyJwt<AppTokenPayload>(appToken);
  } catch {
    return Response.json({ error: "Invalid token" }, { status: 401 });
  }

  const { instId, settings } = payload;
  // instId is the installation ID, settings contains persisted installation config
}
```

`verifyJwt` reads `STELLARTOOLS_APP_SECRET` and `STELLARTOOLS_APP_ID` from your environment — no extra arguments needed.

### Call the StellarTools API from your BFF

Forward the `appToken` as `x-stellartools-app-token` when calling StellarTools server-to-server:

```ts
function stellarFetch(path: string, appToken: string, init?: RequestInit) {
  return fetch(`${process.env.STELLARTOOLS_API_URL}${path}`, {
    ...init,
    headers: { ...init?.headers, "x-stellartools-app-token": appToken },
  });
}

// Example: read installation settings
const res = await stellarFetch(`/installations/${instId}/settings`, appToken);
const settings = await res.json();

// Example: patch installation settings
await stellarFetch(`/installations/${instId}/settings`, appToken, {
  method: "PATCH",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ myKey: "value" }),
});
```

### Settings — persisting configuration

Installation settings are stored as a JSON object in the `appInstallations.settings` column. Use them to store anything the merchant configures — API keys, preferences, notification rules, etc.

```ts
// Save a setting
await stellarFetch(`/installations/${instId}/settings`, appToken, {
  method: "PATCH",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ resendApiKey: "re_xxx", syncEnabled: true }),
});

// Read settings (also available in the decoded appToken payload as `settings`)
const res = await stellarFetch(`/installations/${instId}/settings`, appToken);
const { resendApiKey, syncEnabled } = await res.json();
```

<Note>
  Settings are also embedded in the signed `appToken` payload as the `settings` field, so BFF routes that just need to read config can decode the token instead of making an extra round-trip.
</Note>

### Environment variables

Add these to your marketplace app's `.env`:

```env
STELLARTOOLS_APP_SECRET=sec_...   # Your app's signing secret — used to verify appTokens
STELLARTOOLS_APP_ID=app_...       # Your app's ID — used as the JWT issuer
STELLARTOOLS_API_URL=https://api.stellartools.dev
WEBHOOK_SECRET=whsec_...          # Secret for verifying incoming webhook payloads
```

## Define your manifest

When submitting your app you provide a manifest that declares exactly what it needs. Users see your scopes and events before they install.

```json
{
  "name": "My App",
  "description": "A short description shown in the marketplace (max 200 chars).",
  "homepageUrl": "https://myapp.com",
  "baseUrl": "https://myapp.com/stellartools",
  "webhookUrl": "https://myapp.com/api/webhooks/stellar",
  "scopes": ["read:customers", "read:payments"],
  "version": "1.0.0"
}
```

<ParamField body="name" type="string" required>
  Display name shown in the marketplace. 2–50 characters.
</ParamField>

<ParamField body="description" type="string" required>
  Short description shown on the listing card. Max 200 characters.
</ParamField>

<ParamField body="homepageUrl" type="string" required>
  Your app's public homepage.
</ParamField>

<ParamField body="baseUrl" type="string" required>
  The URL StellarTools loads inside the iframe. Context params are appended as query strings automatically.
</ParamField>

<ParamField body="webhookUrl" type="string">
  If provided, StellarTools will POST signed event payloads here. Omit if you don't need event subscriptions.
</ParamField>

<ParamField body="scopes" type="string[]" required>
  At least one scope is required. Declare only what your app actually needs — users see the full list before installing.
</ParamField>

<ParamField body="version" type="string">
  Semantic version of your app. Defaults to `1.0.0`.
</ParamField>

## Scopes

Scopes follow the pattern `read:resource` or `write:resource`.

| Scope                                            | What it grants                                                      |
| ------------------------------------------------ | ------------------------------------------------------------------- |
| `read:customers` / `write:customers`             | Customer records                                                    |
| `read:payments` / `write:payments`               | Payment history and status                                          |
| `read:subscriptions` / `write:subscriptions`     | Subscription lifecycle                                              |
| `read:checkouts` / `write:checkouts`             | Checkout sessions                                                   |
| `read:payouts` / `write:payouts`                 | Payout records                                                      |
| `read:refunds` / `write:refunds`                 | Refund records                                                      |
| `read:payment_methods` / `write:payment_methods` | Saved payment methods                                               |
| `read:products` / `write:products`               | Product catalog                                                     |
| `read:portal`                                    | Customer portal sessions                                            |
| `*`                                              | All resources — shown prominently to users, use sparingly           |

## Webhook events

When a matching event fires, StellarTools POSTs a signed payload to your `webhookUrl`.

### Verify the signature

Every webhook request includes an `x-stellartools-signature` header (`sha256=<hex>`). Always verify it before processing:

```ts
import { createHmac, timingSafeEqual } from "crypto";

function verifySignature(rawBody: string, signature: string | null): boolean {
  if (!signature) return false;
  const expected = `sha256=${createHmac("sha256", process.env.WEBHOOK_SECRET!).update(rawBody).digest("hex")}`;
  const a = Buffer.from(expected);
  const b = Buffer.from(signature);
  return a.length === b.length && timingSafeEqual(a, b);
}
```

### Handle events

```ts
import type { WebhookEvent } from "@stellartools/core";
import { createHmac, timingSafeEqual } from "crypto";

export async function POST(req: Request) {
  const rawBody = await req.text();
  const signature = req.headers.get("x-stellartools-signature");
  const expected = `sha256=${createHmac("sha256", process.env.WEBHOOK_SECRET!).update(rawBody).digest("hex")}`;

  if (!signature || !timingSafeEqual(Buffer.from(expected), Buffer.from(signature))) {
    return Response.json({ error: "Invalid signature" }, { status: 401 });
  }

  const { event, settings } = JSON.parse(rawBody) as { event: WebhookEvent; settings: Record<string, unknown> };

  switch (event.type) {
    case "payment.confirmed":
      await syncPayment(event.data.object);
      break;
    case "subscription.canceled":
      await handleChurn(event.data.object);
      break;
    case "checkout.created":
      if (settings.syncEnabled) await syncContact(event.data.object);
      break;
  }

  return Response.json({ ok: true });
}
```

<Note>
  StellarTools includes the installation's `settings` object alongside every webhook event so your handler can read merchant configuration (like feature flags or API keys) without a round-trip.
</Note>

### Available events

| Event                    | Fires when                      | `data.object` type |
| ------------------------ | ------------------------------- | ------------------ |
| `payment.confirmed`      | A payment is confirmed on-chain | `Payment`          |
| `payment.pending`        | A payment is pending            | `Payment`          |
| `payment.failed`         | A payment fails                 | `Payment`          |
| `refund.succeeded`       | A refund is issued              | `Refund`           |
| `refund.failed`          | A refund fails                  | `Refund`           |
| `subscription.created`   | A subscription starts           | `Subscription`     |
| `subscription.updated`   | A subscription is modified      | `Subscription`     |
| `subscription.canceled`  | A subscription is canceled      | `Subscription`     |
| `checkout.created`       | A checkout session opens        | `Checkout`         |
| `customer.created`       | A new customer is created       | `Customer`         |
| `customer.updated`       | Customer details change         | `Customer`         |
| `customer.deleted`       | A customer is deleted           | `Customer`         |
| `payment_method.created` | A payment method is saved       | `CustomerWallet`   |
| `payment_method.deleted` | A payment method is removed     | `CustomerWallet`   |
