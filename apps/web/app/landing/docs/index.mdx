StellarTools is a payments platform built on [Stellar](https://stellar.org). You can use it to accept crypto payments, run subscriptions, charge by usage, and pay out to local currencies. Payments settle in a few seconds for fractions of a cent.

**What you can build with it:**

- One-time and recurring checkout pages
- Subscription billing with pause, resume, and cancellation
- Customer portals where users manage their own subscriptions and invoices
- Global payouts to local currencies (NGN, KES, GHS, and more)

## Get your API key

There are two ways to use StellarTools:

- **[dashboard.stellartools.dev/api-keys](https://dashboard.stellartools.dev/api-keys)** — create a free StellarTools account and get an API key in seconds. No infrastructure to run.
- **[Self-host it](/self-hosting/quickstart)** — run your own instance with one `docker compose up` command. You own the infrastructure, the database, and the Stellar keys.

Either way, create a new key and copy it. The key encodes your environment (testnet or mainnet), so you do not need to set any base URLs or environment flags — unless you're self-hosting with a custom API URL, see [Self-Hosting](/self-hosting/configuration).

<Note>Use testnet keys while building. Switch to a mainnet key when you are ready to go live.</Note>

## Install the SDK

```bash
npm install @stellartools/core
```

```ts
import { StellarTools } from "@stellartools/core";

const st = new StellarTools({
  api_key: process.env.STELLAR_TOOLS_API_KEY!,
});
```

That is all the setup you need. From here, `st.customers`, `st.checkout`, `st.subscriptions`, and the rest are ready to use.

## API versioning

Every request is pinned to a specific API version via the `StellarTools-Version` header. The SDK defaults to the latest version (`2026-08-18`). To lock your integration to a specific version, pass `version` at initialization:

```ts
const st = new StellarTools({
  api_key: process.env.STELLAR_TOOLS_API_KEY!,
  version: "2026-08-18",
});
```

You can also override the version per-request using the `options` argument on any method:

```ts
const customer = await st.customers.create(
  { email: "...", name: "..." },
  { version: "2026-08-18" }
);
```

Webhook events and delivery logs always record the API version that was active when the event fired, so you can correlate events to the version your code was running against.
